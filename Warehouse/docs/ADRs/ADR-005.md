# ADR 005: Immutable Transaction History for Inventory and Orders

## Status
Accepted

## Context
Several features (Inventory Counting, Receiving, Shipping) require historical data to be preserved. For example, a supplier order with receiving history must not be deleted, just canceled (Feature 9). An inventory adjustment must record who made it and why (Feature 4). 

## Decision
We will use an append-only (immutable) transaction history for inventory movements, order statuses, and receipts. We will not hard-delete records that are referenced by transactions. Instead, we will use "soft deletes" (an `active_status` flag) for master data (Items, Customers, Suppliers).

## Consequences
- **Positive:** Perfect audit trails. If stock is wrong, we can trace exactly who moved what, when, and where. Reports (Feature 18) become highly reliable.
- **Negative:** The database will grow faster since we never delete data. Queries for "active" records must always include the `active_status = true` filter.
