# ADR 004: Role-Based Access Control (RBAC)

## Status
Accepted

## Context
The system serves different types of users (Feature 7: Employee Maintenance). Office employees manage company data and orders, warehouse workers adjust inventory and pick orders, truck drivers record deliveries, and managers view reports. Unauthorized access to certain functions (e.g., a driver adjusting inventory) must be prevented.

## Decision
We will implement Role-Based Access Control (RBAC). Every Employee record will be assigned one or more Roles (Office, Warehouse, Driver, Manager). The backend API will enforce permissions based on the user's role extracted from their authentication token.

## Consequences
- **Positive:** Centralized security. The frontend can hide UI elements the user cannot access, while the backend ensures no malicious API calls bypass the rules.
- **Negative:** Requires maintaining a mapping of roles to permissions in the backend, which adds some overhead when adding new features.
