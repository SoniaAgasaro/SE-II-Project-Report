# ADR 002: RESTful API for Client-Server Communication

## Status
Accepted

## Context
With the decision to use a client-server architecture (ADR-001), we need a standardized way for the frontend to communicate with the backend. The system will handle various entities: Items, Orders, Inventory, and Users.

## Decision
We will use REST (Representational State Transfer) over HTTP/HTTPS for the API. Data will be exchanged using JSON. We will follow standard HTTP methods (GET, POST, PUT, PATCH, DELETE) and HTTP status codes (200, 400, 404, 500) to represent state and errors.

## Consequences
- **Positive:** Highly standardized, easy to document (via Swagger/OpenAPI), and natively supported by almost all modern frontend frameworks.
- **Negative:** REST can sometimes require multiple round-trips to fetch complex, nested data (e.g., an Order with its Order Lines).
