# ADR 001: Client-Server Architecture

## Status
Accepted

## Context
The Warehouse System needs to support multiple concurrent users (office staff, warehouse workers, drivers) while maintaining strict data integrity. Warehouse operations often require real-time updates (e.g., preventing two pickers from grabbing the same stock simultaneously). 

## Decision
We will use a client-server architecture. The frontend will be a browser-based UI (and potentially mobile-friendly views for scanners), communicating with a backend REST API. The backend will handle all business logic and database transactions.

## Consequences
- **Positive:** Centralized data integrity and business logic. Easier to maintain and update since the UI is decoupled from the database.
- **Negative:** Requires constant network connectivity for warehouse workers. If the network drops, operations may halt unless offline capabilities are built into the client.
