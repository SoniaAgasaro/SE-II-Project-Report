# ADR 003: Relational Database and ORM

## Status
Accepted

## Context
The system's data model is highly relational. Customers have Orders, Orders have Lines, Items have Suppliers, and Inventory Balances link Items to Locations. Data integrity (e.g., no orphaned order lines, enforcing unique SKUs) is critical.

## Decision
We will use a Relational Database Management System (RDBMS) like PostgreSQL or MySQL. We will use an Object-Relational Mapper (ORM) (e.g., Prisma, Entity Framework, or SQLAlchemy depending on the backend stack) to define the schema, manage migrations, and handle queries.

## Consequences
- **Positive:** Strong ACID compliance ensures that inventory adjustments and order creations are atomic. The ORM speeds up development and prevents SQL injection.
- **Negative:** ORMs can sometimes generate inefficient queries for complex reporting (Features 18 and 19), requiring raw SQL fallbacks.
